1The idea

The demo worked, but setting it up took nine steps, several of them easy to forget after a restart (install packages, create audio devices, launch Chrome, start the watcher in the background, find the noVNC URL). E6 makes it something a non-developer can run: the container installs itself, make demo starts everything and walks through the QR scan, and make doctor says what is wrong and exactly how to fix it. A separate, untested WINDOWS.md covers WhatsApp Desktop with VB-Cable.

2How it works

The noVNC URL is built from the Codespaces variables CODESPACE_NAME and GITHUB_CODESPACES_PORT_FORWARDING_DOMAIN, with http://localhost:6080/… as the fallback.

4Results

All 15 doctor checks pass in this Codespace. The failure paths were checked where that was possible without touching the live setup: Chrome unreachable (closed port), .env missing (a copy of the scripts), and the WhatsApp QR state (a separate throwaway headless Chrome). make sim answered 4/4 turns, median latency 1.35 s (p90 1.39 s), in line with E0. The Windows adapter ran a real realtime session against a stub audio backend and answered "What is the capital of France?" correctly.

5What worked, what didn't, what's next

Worked

  • The whole manual run order collapses to: create the Codespace, fill in .env, make demo, scan the QR.
  • make doctor covers every failure seen so far (audio devices, Chrome, login, gateway, realtime key) with a copy-paste fix.
  • The login check reads the page only, so it is safe to run next to a live call.
  • The Windows adapter reuses the realtime agent unchanged: it swaps parec/pacat for sounddevice streams.

Didn't

  • A container rebuild could not be tested from inside the container: the postCreate/postStart path is untested end to end.
  • A GET on the gateway root timed out once while the API itself worked, so reachability is now a TCP/TLS connect.
  • WhatsApp Desktop has no CDP, so the Windows path has no auto-answer: the user clicks Accept.

Next

  • Rebuild a fresh Codespace and time create → first call.
  • Try the Windows path on a real PC with VB-Cable.
  • Optionally prebuild the Chrome/PulseAudio layer into a Dockerfile to cut create time.

6How to run it

# Codespace: dependencies install on create, audio devices on every start
cp scripts/.env.example scripts/.env   # your OpenAI-compatible LLM gateway URL + token
make demo        # audio + Chrome + auto_answer, prints the noVNC URL, waits for the QR scan
make doctor      # read-only health check, a fix for every failure (ARGS=--redact to share it)
make sim         # simulated call, no phone (TAG=E6 names the run)
make stop        # stop auto_answer (bash scripts/demo.sh stop --chrome also closes Chrome)
make demo-dry    # show what make demo would do, change nothing

# without make
bash scripts/demo.sh [--dry-run|--no-wait|stop]
python3 scripts/doctor.py [--offline|--redact|--url|--wait-login SECS]

# Windows (untested): WhatsApp Desktop + two VB-Cables, see WINDOWS.md
python scripts\win_agent.py --list
python scripts\win_agent.py --in "CABLE-A Output" --out "CABLE Input" --wait
