E5 · "Call me and I'll play it": audio on demand

DONE

1The idea

You call the WhatsApp number and say "play the latest team update" or "make me a one-minute podcast about Project Nimbus", and the AI plays it into the call. Mode A plays files from a media/ folder with voice controls (pause, continue, next, stop, louder). Mode B has an LLM write a two-host script from the knowledge/ folder, voices it with two TTS voices and plays it. The realtime agent stays on the line throughout: if you start talking, the audio pauses and the agent answers.

All test content is fictional ("Lumen Labs", "Project Nimbus"). The media is our own: a TTS team update and synthesized chords, generated by experiments/E5/make_media.py. No third-party music.

2How it works

  • Pause on speech. The realtime API sends input_audio_buffer.speech_started as soon as the caller talks. The player stops writing audio at once; only ~0.1 s is queued in pacat.
  • No talking over the media. Tools return immediately; the model says one short line ("Here's the team update"), and playback starts only after that reply has been generated and played out (we count the audio bytes the model sent).
  • Podcast streaming. The episode is played while it is still being synthesized: playback starts as soon as line 1 is ready (~6 s), the other lines arrive faster than real time.

3Demo

The caller's lines were transcribed by speech-to-text, which sometimes writes the Indian-English TTS caller in Urdu or Devanagari script, and transcribes music as junk words. The caller actually said the lines in experiments/E5/scripts/*.yaml. Media playback appears as long AGENT segments.

4Results

Two simulated calls (E0 harness): media_controls (play the team update → interrupt with a question → "continue" → "next" → "louder" → "stop") and podcast (1-minute podcast → question mid-podcast → "continue" → "stop"). Every command was carried out correctly and every interruption paused the audio.

Response times

"Caller stops talking" is the server's speech_stopped event, which fires ~0.5 s after the voice really ends, so add ~0.5 s for the caller's perceived wait. Most of the wait is the model's spoken acknowledgement (~1–2 s to start + ~1.5 s of speech) before the media starts.

5What worked, what didn't, what's next

Worked

  • All 8 voice commands in the two published calls (and the 2 earlier runs) triggered the right tool: play, continue, next, louder, stop, podcast.
  • Talking over the media silenced it in a median 0.43 s (12 barge-ins), faster than the agent's own barge-in in E0 (~1.5 s).
  • Mid-podcast question ("How much budget?") got the right answer from knowledge/ ("18 lakh rupees"), then "Shall I continue?", then resumed where it paused.
  • Podcast playable after ~6 s (LLM script ~4 s + first TTS line ~2 s); whole 1-minute episode synthesized in ~15 s with gateway TTS, faster than it plays.
  • The agent never talked over the media: playback waits for its one-line acknowledgement.

Didn't

  • "Play X" takes ~4.5 s until the media starts, mostly the spoken "Here's X" acknowledgement.
  • "1-minute" podcasts came out 55–78 s: the LLM overshoots its word budget (budget now lowered to 110 words/min).
  • A caller line with a pause ("Okay, thanks. Continue please.") is two turns, so resume_media was called twice (harmless).
  • Any sound from the caller pauses the media; there's no auto-resume for coughs or "mm-hm" yet.
  • edge-tts voices are ~3× slower to synthesize than gateway TTS (43 s for a 61 s episode), still just ahead of playback.

Next

  • Real WhatsApp call: check media loudness vs the voice and that Chrome's echo cancellation doesn't treat media as echo.
  • Auto-resume when the "interruption" turns out to be noise (empty transcript).
  • Skip the spoken acknowledgement (or play a short chime) to cut command → playback to ~2 s.
  • Cache generated podcasts per topic, and use E1's context loader once it lands.

6How to run it

python3 experiments/E5/make_media.py        # generate the test media (git-ignored mp3s)

# standalone: the agent on any pair of PulseAudio devices
python3 scripts/media_agent.py --context experiments/E5/context --seconds 120 \
    --in-device callout_E5.monitor --out-device virtmic_E5

# simulated calls (E0 harness)
AGENT="{python} scripts/media_agent.py --context experiments/E5/context --seconds {seconds} \
  --in-device {in_device} --out-device {out_device} --transcript {transcript}"
python3 scripts/sim_call.py experiments/E5/scripts/media_controls.yaml --tag E5 --max-seconds 200 --agent "$AGENT"
python3 scripts/sim_call.py experiments/E5/scripts/podcast.yaml --tag E5 --max-seconds 200 --agent "$AGENT"

# podcast only (prints timings)
python3 scripts/podcast.py --knowledge experiments/E5/context/knowledge --topic "Project Nimbus" --minutes 1 --out pod.mp3

Context folder: instructions.md, config.yaml (voice, greeting, media.podcast_voices), knowledge/, media/ + optional media/catalog.yaml (title, description, tags per file). Each run also writes media_events.jsonl (timings) and, for podcasts, podcast.mp3 + podcast_script.json.
