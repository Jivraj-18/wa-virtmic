E1 · "Call center" mode controlled from a folder

DONE

1The idea

The owner keeps three things in a folder: instructions.md (for example, "I'm travelling 2–6 pm, I'll call back"), config.yaml (voice, language, greeting, maximum call length) and a knowledge/ folder of notes and PDFs. One command, callcenter.py start, makes WhatsApp answer calls as the owner's assistant, using those files. After every call, the owner gets a summary.md that says who called, what they wanted, what the AI promised and what to follow up.

2How it works

Phase 1 pastes the knowledge files directly into the voice model's instructions, capped at 24,000 characters. E2 handles larger folders by searching them with tool calls. Without --context, auto_answer.py works exactly as before.

5What worked, what didn't, what's next

Worked

  • All 12 caller turns got an answer. Of the 7 answers checked against the folder, 6 matched fully and 1 partly.
  • The release and beta dates came straight from the knowledge note. The price, which isn't in the notes, was correctly passed back to Alex.
  • The agent kept the rule "never say where I'm travelling". It took a message and read it back.
  • The custom greeting from config.yaml played word for word, about 0.5 s after the agent started.
  • The summary.md for each of the three runs was accurate and listed the right follow-ups. Each took about 2 s with gpt-4.1-mini.
  • start, stop and status work, and edits to instructions.md are picked up on the next reload.

Didn't

  • It hasn't been tried on a real WhatsApp call yet, because the live watcher was off limits during this experiment.
  • The caller's name is guessed from the incoming-call popup text. This hasn't been tested on WhatsApp's real page.
  • At 9 am the agent said "Alex will be free after 6 pm", although the instructions said not to promise an exact time before 2 pm.
  • Latency is 0.1–0.2 s higher than in E0 (median 1.41–1.55 s), probably because the instructions are longer.
  • As in E0, a pause in the middle of the caller's sentence still cuts a reply off early.

Next

  • Make one real call to check the caller name and summary.md (steps are in RESULTS.md).
  • Time zone: the agent uses the machine's clock, which is UTC in the Codespace. Set TZ to the owner's time zone.
  • E2: search a larger knowledge/ folder with tool calls instead of pasting it into the instructions.
  • Optional: hang up when max_call_seconds is reached. Right now the agent only stops talking.

6How to run it

cp -r callcenter.example callcenter      # your real folder (git-ignored); edit the files in VS Code
python3 scripts/callcenter.py start --context callcenter --check     # validate + print the built instructions
python3 scripts/callcenter.py start --context callcenter --dry-run   # stand-in watcher, no Chrome: try status/stop
python3 scripts/callcenter.py status
python3 scripts/callcenter.py stop

# real mode (Chrome with WhatsApp Web on :9222; refuses if another auto_answer.py is running)
python3 scripts/callcenter.py start --context callcenter
#   -> scripts/calls/<ts>/{transcript.txt, transcript_live.txt, summary.md, call_mix.mp3 ...}

# simulated calls against the context-built agent
python3 scripts/sim_call.py experiments/E1/scripts/g5_release.yaml --tag E1 \
  --agent "{python} scripts/callcenter.py agent --context callcenter.example --in-device {in_device} --out-device {out_device} --transcript {transcript} --seconds {seconds}"
python3 scripts/callcenter.py summarize experiments/runs/E1_g5_release_<ts> --context callcenter.example

The config.yaml keys are owner_name, voice, language, max_call_seconds, greeting and answer_only, a list of caller-name substrings. An empty list answers everyone.
