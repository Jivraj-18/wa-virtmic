E2 · "Hold on, let me check": tool calls mid-call

DONE

1The idea

A caller asks something that only appears deep inside the project documents. The voice agent says "Give me a moment, I'm checking the documents", looks it up while the line stays live, and then gives the answer. Fast lookups use a keyword search over the files. Questions that combine several documents go to a slower background agent (claude -p), which reads the files and works the answer out.

2How it works

The holding lines are sent as out-of-band responses that can't see the conversation. Before that change, one "still checking" line made up a wrong total while the tool was still running. A new response is only requested when none is active, which the realtime API requires. If claude -p fails (for example, a usage limit), ask_agent falls back to a single LLM call over all documents, then to search snippets.

4Results

Each row is one caller question that needed a tool. To first audio: from the end of the caller's voice to the agent's first sound, which is the holding line. To answer: to the first sound of the actual answer. Both are measured on the recorded audio. "Model's own" means the voice model said a short "let me check" itself before calling the tool. "Forced filler" is our scripted line for slow tools.

The synthesis still run uses a "still checking" interval of 4 s (the default is 15 s) to test the repeat path. In synthesis fallback, claude is disabled on purpose, so the gateway LLM tier answers.

5What worked, what didn't, what's next

Worked

  • 14 of 14 tool questions in the published runs were answered correctly, including facts on "page 5" of a long spec, inside a price table, on page 2 of a PDF, and a 3-file calculation (30 × ($2,340 + $410) = $82,500).
  • The caller always heard something within 1.2–2.2 s: either the model's own "let me check" or the forced filler.
  • Fast lookups (search, ~20 ms) were answered 3.1–4.4 s after the caller stopped. The claude -p research agent took 6.6–7.9 s, and its answer arrived at 8.7–11.4 s.
  • When the research agent failed, the call kept going: the gateway LLM tier answered in 2.5 s, and with snippets only the agent offered a call back instead of guessing.

Didn't

  • A "still checking" line inside the conversation once made up an answer ("$320,000") just before the real one. It was fixed with out-of-band holding lines.
  • The model's own preface costs time: answers came 2.9 s after the caller stopped without it and 4.0 s with it. Without it, though, the caller hears about 3 s of silence.
  • The shared Claude account hit its usage limit mid-experiment, so claude -p exited 1 within 3 s.
  • With snippets only, the voice model did not do the arithmetic itself.

Next

  • Wire into E1's call center: tools.agent_kwargs() combined with end_call.
  • For small folders, try a single LLM call over all documents as the main research step: 2.5 s vs about 7 s.
  • Test with real callers: does a 9 s wait with one holding line feel OK on a phone?

6How to run it

sudo apt-get install -y ripgrep poppler-utils     # rg + pdftotext
# try the tools directly
python3 scripts/tools.py search "firmware freeze" --context experiments/E2/context
python3 scripts/tools.py ask "Total first-year cost of the pilot fleet incl. extended warranty?" --context experiments/E2/context

# simulated call (E0 harness) with the tool-enabled agent
python3 scripts/sim_call.py experiments/E2/scripts/synthesis.yaml --tag E2 \
  --agent "{python} scripts/tools.py agent --context experiments/E2/context --seconds {seconds} \
           --in-device {in_device} --out-device {out_device} --transcript {transcript}"
python3 experiments/E2/tools/analyze_run.py experiments/runs/E2_synthesis_<ts>   # time to filler / answer, correctness
python3 scripts/publish_run.py experiments/runs/E2_synthesis_<ts> --id E2

Options: --no-preface (the model stays silent before tool calls), environment variables E2_ASK_MODEL (default sonnet), E2_ASK_TIMEOUT (90 s), E2_STILL_EVERY (15 s), E2_FILLER_AFTER (1.5 s) and E2_LLM_FALLBACK_MODEL (gpt-4.1-mini, empty to disable). Each run folder gets tool_calls.jsonl, e2_events.jsonl and tool_timing.csv.
