# E2 results: "Hold on, let me check": tool calls into local files and a background agent

**Status: DONE** (2026-11-18). Site page: `docs/E2.html`. Simulated calls only (E0 harness). No real WhatsApp call was made.

## What was built
- `scripts/tools.py` (new module):
  - `search_knowledge(query)`: ripgrep over the context folder. PDFs are searched through a cached `pdftotext` mirror.
    Light stemming, then rarer terms get more weight in ±3-line windows. Returns the top 5 snippets with file, line
    and PDF page.
  - `read_file(path, start_line)`: restricted to the context folder (paths that escape it are rejected), returns
    12k-char chunks, and reads PDFs as text.
  - `ask_agent(question)`: `claude -p` headless with cwd = the context folder, model `sonnet`, and only Read/Grep/Glob
    allowed (Bash, Edit, Write, Web* and Task are disallowed). No session persistence, 90 s timeout. On failure it falls
    back to **(2)** one chat completion over all the context text via the OpenAI-compatible LLM gateway
    (`gpt-4.1-mini`), then **(3)** the top search snippets.
  - `E2Session` (the filler controller). For `ask_agent`, or any tool still running after 1.5 s, it waits until no
    response is active and then speaks "Give me a moment, I'm checking the documents." That step is skipped if the model
    already said its own "let me check" in this turn. After that, "Still checking, thanks for waiting." plays every 15 s
    of silence (at most 4 times). Holding lines are **out-of-band responses** (`conversation: "none"`, fixed input,
    `tool_choice: none`). Before returning a result it waits for `response.done`, so the Agent's automatic
    `response.create` never collides with an active response.
  - Logs: `tool_calls.jsonl` (every call: args, full result, timing, holding lines) and `e2_events.jsonl` (response,
    audio and VAD timeline), both written to the run/call folder.
  - `agent_kwargs(context_dir, log_dir)` returns `{"tools", "on_tool", "on_event", "instructions_suffix"}`. `on_tool`
    returns `None` for tools it doesn't own. `chain_on_tool(...)` and `chain_on_event(...)` combine it with other
    handlers.
  - CLI: `tools.py search|read|ask ... --context DIR` and `tools.py agent --context DIR --in-device .. --out-device ..
    --transcript .. [--no-preface]`, which is the harness `--agent`.
- `experiments/E2/context/`: a fictional "Kestrel K2 delivery drone" programme. All names and companies are invented.
  - `knowledge/kestrel_k2_spec.md` (~6.8k words, 380 lines): key facts are buried among about 250 filler requirement
    rows. The firmware freeze is on line 311.
  - `knowledge/pricing_2027.md`: plan and add-on tables.
  - `knowledge/meeting_notes_oct_nov_2026.txt`: 6 meetings. The fleet grows from 24 to 30 drones in the 5th meeting.
  - `knowledge/warranty_policy.pdf`: 2 pages. Warranty facts are on page 2. It is generated by
    `experiments/E2/tools/make_warranty_pdf.py`.
- `experiments/E2/scripts/*.yaml`: `deep_facts` (4 single facts), `synthesis` (a 3-file calculation that needs
  `ask_agent`, plus 1 fact), and variants `deep_facts_nopreface`, `synthesis_still` and `synthesis_fallback` (same lines,
  different agent settings). Lines carry `expect:` answers.
- `experiments/E2/tools/analyze_run.py`: maps the agent's wall-clock events onto the recorded audio, aligned on the
  greeting onset, with a playback-queue model and snapping to real voice onsets in `agent.wav`. Writes
  `tool_timing.csv` and adds `summary.json["e2"]`, which goes into the docs. It also checks correctness against
  `expect:`.

## Results (published runs, gpt-realtime, server VAD 500 ms)
Times are measured on the recorded audio, from the end of the caller's voice.

| deep_facts | Fleet plan price | search + read_file | 0.02 s | model's own | 1.50 s | 4.13 s | yes ($2,340) |
| deep_facts | who files noise paperwork, by when | search | 0.01 s | model's own | 1.30 s | 3.08 s | yes (Ravi Menon, 20 Nov) |

**14 of 14 tool questions were correct.** Time to the first audio (the holding line): 1.2–1.5 s when the model says
it itself, 2.0–2.2 s with the forced filler (it waits for the function-call response to finish). Time to answer:
3.1–4.4 s for search, 8.7–11.4 s for `claude -p`, 5.6 s for the gateway fallback.

Superseded runs (local only, not published):
- First synthesis run, sonnet: correct, answer at 12.4 s, tool 10.1 s.
- Synthesis run with `E2_ASK_MODEL=opus`: correct, tool 10.8 s, answer at 13.2 s. Opus wasn't slower here.
- **Bug run:** with the old in-conversation "still checking" line, the model said *"Thanks for waiting, I've got the
  details now… the total… is $320,000"* before the tool had returned, then gave the correct $82,500. The analyzer
  scored it "correct" because it only checks the answer response. That led to the out-of-band holding lines; the re-run
  was clean (verbatim lines, no made-up number).
- Snippet-only fallback (before the gateway tier existed): the voice model read out the price and warranty but did not
  compute the total. It said it couldn't calculate it right now and offered a call back. No wrong number.
- One synthesis run failed because the shared Claude account hit its **5-hour usage limit**: `claude -p` exits 1 in
  about 3 s and prints the reason on stdout, not stderr. The agent apologised and offered a call back. That run was
  deleted. This is why the gateway fallback tier exists.

## Findings
- **It works end to end.** The realtime model picks the right tool by itself: `search_knowledge` for single facts and
  `ask_agent` for the "work out the total… check all the documents" question. It sometimes adds a `read_file`.
- **Holding lines.** For fast tools the model's own "Let me check that" (with `PREFACE_MODEL` in the instructions)
  starts at 1.3 s, but the answer then waits for that phrase to finish: about 4.0 s median vs 2.9 s with
  `--no-preface`. With `--no-preface` the caller hears about 3 s of silence instead. Default: preface on, because it
  feels more natural on a call.
- **Holding lines must not see the conversation.** An in-conversation response with "say only that you're still
  checking" can still answer the question, and wrongly. Out-of-band responses fixed this and made the lines verbatim.
- **The realtime API allows one active response at a time.** The controller tracks `response.created`/`response.done`
  and always waits for idle before `response.create`. No `conversation_already_has_active_response` errors occurred in
  the final runs.
- **The research agent is slower than needed for small folders.** `claude -p` took 6.6–10.8 s (about 11 s even for
  "reply OK"; process start-up plus agent turns). One `gpt-4.1-mini` call over all about 45 KB of documents took
  2.3–2.5 s and was also correct. For call-center folders under about 100k characters that may be the better primary
  path, with `claude -p` kept for big folders.
- Search ranking is simple but good enough: the right snippet was in the top 2 for every question. The meeting-notes
  line "Freeze date as per spec" ranks above the spec itself, and the model followed up correctly anyway.
- STT quirk (from E0): the caller's "Great" is sometimes transcribed in Urdu script. Only the transcript is affected.

## How to run
```bash
sudo apt-get install -y ripgrep poppler-utils
python3 scripts/tools.py search "firmware freeze" --context experiments/E2/context
python3 scripts/tools.py ask "Total first-year cost for the Kochi pilot fleet incl. extended warranty?" --context experiments/E2/context
AGENT="{python} scripts/tools.py agent --context experiments/E2/context --seconds {seconds} --in-device {in_device} --out-device {out_device} --transcript {transcript}"
python3 scripts/sim_call.py experiments/E2/scripts/deep_facts.yaml --tag E2 --agent "$AGENT"
python3 scripts/sim_call.py experiments/E2/scripts/synthesis.yaml  --tag E2 --agent "$AGENT"
# variants: add --no-preface to AGENT (deep_facts_nopreface.yaml); E2_STILL_EVERY=4 (synthesis_still.yaml);
#           CLAUDE_BIN=/bin/false (synthesis_fallback.yaml)
python3 experiments/E2/tools/analyze_run.py experiments/runs/E2_<script>_<ts>
python3 scripts/publish_run.py experiments/runs/E2_<script>_<ts> --id E2
```
Environment variables: `E2_ASK_MODEL` (sonnet), `E2_ASK_TIMEOUT` (90), `E2_STILL_EVERY` (15), `E2_FILLER_AFTER` (1.5),
`E2_LLM_FALLBACK_MODEL` (gpt-4.1-mini, empty to disable), `CLAUDE_BIN`.

## Integration note for E1 (call center, `scripts/context.py` / `auto_answer.py` on main)
E2 is a plug-in; no changes to `context.py` are needed. In `auto_answer.handle_call` (realtime branch with `ctx`):
```python
import tools
e2 = tools.agent_kwargs(ctx["path"], d, log=log)          # d = calls/<ts>/ -> tool_calls.jsonl, e2_events.jsonl
agent = make_agent(ctx, caller, extra={
    "tools": [END_CALL_TOOL] + e2["tools"],
    "on_tool": tools.chain_on_tool(e2["on_tool"], on_tool),  # E2 first: it returns None for end_call
    "on_event": e2["on_event"],                               # required: drives holding lines + response tracking
    "instructions": build_instructions(ctx, caller) + hang + e2["instructions_suffix"]},
    transcript=d / "transcript_live.txt", log=log)
```
- `ctx["path"]` is the context folder. `media/` is ignored by the tools.
- E1's phase-1 knowledge stuffing (24k chars) and the E2 tools can coexist. For big folders, rely on the tools.
- The `claude` CLI must be installed and logged in on the host, otherwise the gateway tier answers.

## Shared-file changes
- `scripts/sim_call.py`: an optional per-line `reply_timeout:` and `until_quiet:` (after the reply, keep following
  agent speech until it is quiet for N seconds, for filler → answer). Backward compatible: a new `wait_turn()` helper
  is used only where the old `wait_reply` was called, and it behaves the same without those keys. Unknown keys such as
  `expect:` are ignored.
- No changes to `realtime_agent.py`, `auto_answer.py`, `transcribe.py`, `speak.py` or `gateway.py` (`tools.py`
  imports `gateway` read-only).
